# Region Launcher 0.2.0（环境验证版）

在 Windows 宿主机上运行指定的 x64 程序，按本次启动的进程组应用 SOCKS5 代理，并模拟美国地区、英语（美国）及洛杉矶时区。程序保留当前用户原有的文件访问权限。

这是一份经过本机测试的原型，不是完整的安全隔离产品。**Claude Desktop 尚未安装、运行或适配验证，不应将本版本的测试结果视为 Claude 可安全登录的证明。**

## 使用

1. 保持整个 `app` 文件夹完整，运行 `RegionLauncher.exe`。本机已经具备所需的 .NET 10 桌面运行时。
2. 本机已配置专用全代理 `127.0.0.1:17890`，由启动器自动启停。国内外网站统一走导入的美国节点，网站 DNS 经该节点访问加密解析器。点击“检测代理”检查握手。没有私有节点配置的通用压缩包仍使用外部 `7890`，不能据此保证全代理。
3. 选择现有的 x64 `.exe` 并启动，或点击“打开独立浏览器”。网络引擎申请管理员权限，目标程序保留启动器原有权限。
4. “打开独立浏览器”优先查找本机 Chrome，其次 Edge。浏览器有单独的资料目录；若环境已运行，它加入现有进程组。
5. 保存文件后再点击“结束本次运行”。结束环境会终止组内全部进程。关闭启动器时也会结束环境，界面会提醒保存。

建议先使用“选择环境测试程序”。测试程序很快结束是正常行为，运行记录会显示地区、时区以及子进程的结果。

## 默认配置

| 设置 | 值 |
| --- | --- |
| 国家或地区 | 美国（US） |
| 语言 | English (United States)，en-US |
| 时区 | 洛杉矶，Pacific Standard Time / America/Los_Angeles |
| 自动夏令时 | 开启：冬季 UTC−8，夏季 UTC−7 |
| 关闭自动夏令时 | 全年固定 UTC−8；网页可能显示固定偏移时区 Etc/GMT+8 |
| 代理 | 本机专用 SOCKS5，127.0.0.1:17890；未配置专用节点时为外部 7890 |
| 文件 | 当前用户原有读写权限；不复制到虚拟文件系统 |

界面的“自动切换夏令时与标准时间”在启动前设置。环境运行时配置锁定，结束后可以调整。

程序目录须使用 ASCII 路径。交付目录满足这一条件。

## 浏览器

选择 `chrome.exe` 或 `msedge.exe` 后点击“启动所选程序”，也会转入独立浏览器入口，避免复用外面的窗口；此入口不使用通用的“启动参数”文本框。

专用资料保存在 `app/data/browser/chrome` 或 `app/data/browser/msedge`。它与原有浏览器的资料目录分开，默认不带入原有 Cookie、登录和扩展。

浏览器入口显式配置 SOCKS5、由代理解析网站域名、英语界面与网页语言，并设置限制非代理 WebRTC UDP 的启动选项（尚未进行 WebRTC 泄漏实测）。宿主机原有浏览器配置不被修改。浏览器及普通应用到本机回环地址的通信保留直连，方便本机代理、登录回调和本地工具使用。

浏览器下载、上传及打开文件仍受 Windows 当前用户权限和浏览器自身规则约束。已经安装的 Chrome 已测试；Edge 只有发现和启动入口，尚未实际验证。

外部应用调用 Windows 默认浏览器时，仍可能打开环境外的浏览器。当前版本不修改系统默认浏览器，也未实现 Claude 登录链接的自动接管。需要在独立浏览器中明确打开链接；能否完成某个应用的回调，仍取决于该应用。

## 已知边界

- 普通程序使用 Windows Job Object 区分运行实例。通过系统服务、COM 或已有单实例进程代为执行的工作可能不属于这个进程组；同一程序内外同时运行的能力需要结合目标应用验证。
- 独立浏览器通过专用资料目录处理 Chrome 的单实例复用问题。普通程序没有通用的资料目录和单实例隔离方案。
- 只支持 x64 Windows 可执行程序。x86、受保护进程、部分 MSIX 应用及带额外代码完整性限制的程序未适配。
- 地区和时区通过常见 Windows API 及环境变量模拟。直接读取注册表、使用自带地区库或缓存偏好的应用可能不完全遵从；语言模拟不会安装缺失的语言资源。
- 普通程序委托系统服务解析 DNS 的流量可能绕开进程归属。IPv6、分片、网络切换、驱动重置等情形尚未完整验证。此工具不是可抵抗恶意程序的网络边界。
- 已验证代理拒绝连接时，测试流量不会退回直连。网络引擎退出时会终止本次进程组，但尚未证明崩溃、驱动重置等情况下不存在任何瞬间直连窗口。
- 开源网络引擎经 WinDivert 读取网络包，并按进程组决定处理方式。环境外程序不匹配代理规则，但网络引擎运行期间仍存在驱动和转发处理开销。
- Claude Desktop 的 MSIX 启动、后台服务、更新、登录回调及 Cowork 均未验证；Cowork 自身使用虚拟化。地区与代理设置不能保证账号不受限制。

## 文件位置

- `app/data/profile.json`：启动器偏好。
- `app/data/sessions/`：每次启动的配置与网络日志。
- `app/data/browser/`：独立浏览器资料，请按个人数据妥善保管。
- `app/data/private/proxy.json`：本机节点凭据，仅本机保留，不进入源码或发布压缩包。不要分享此文件。节点使用导入时的服务器 IP，供应商更换入口 IP 或凭据后需重新导入。
- `docs/validation.md`：本机验证记录。

程序不修改宿主机全局代理、DNS、路由、地区或时区，不配置开机启动，不添加全局防火墙放行规则。WinDivert 网络驱动由引擎按需加载，可能在 Windows 中留下驱动服务登记；它不是可省略的用户态依赖。

专用内核的全代理规则没有国内直连分支，不会在节点不可用时回退 7890。它是普通独立进程，不创建全局 TUN。普通应用委托 Windows 服务进行的 DNS 解析仍属于上方已知边界，不能把浏览器检测通过理解成所有应用都完全隔离。

## 构建和验证

依赖：Visual Studio C++ 工具链、.NET 10 SDK、PowerShell 7；测试使用 Python 3 标准库及本机 Chrome。

```powershell
pwsh -NoProfile -File scripts/build.ps1
pwsh -NoProfile -File scripts/fetch_proxy.ps1
python tests/test_locale.py
python tests/test_network.py
python tests/test_browser.py
python tests/test_browser_network.py
```

网络测试会让网络引擎申请管理员权限。测试使用本机模拟 HTTP/SOCKS5 服务，不访问 Claude，不登录账号，不接触原有浏览器资料。浏览器测试中的 Chrome 安装路径和外部时区断言针对本机环境。

ProxyBridge 和 Detours 源码已固定到具体提交。WinDivert 原始归档包含在源码包中，构建时校验哈希并解压。`scripts/patch_core.py` 是首次导入上游源码的修改记录，不要对已经修改的源码重复运行。

来源和许可证见 `docs/SOURCES.md` 与 `vendor` 内许可证。
