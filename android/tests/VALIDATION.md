# Android 验收记录

日期：2026-11-12。目标：vivo X300 / Android 17 / 未 Root。

## 已完成的开发检查

- Android Release 编译、签名。
- Go / NDK 编译 ARM64 和 x86_64 的 Mihomo JNI 库，启用 `cmfa,with_gvisor`。
- JUnit 检查固定节点出口、禁止额外转发、订阅规则隔离、多节点分享链接、Reality、危险 YAML / 重复键、带认证的 SOCKS5、分块 HTTP 响应、无效响应、环境出口不一致。
- Android Lint：无错误，两个“依赖有更新版本”的提示。
- APK 校验：压缩包完整性、签名、无调试标志、两种 ABI、16 KiB ELF LOAD 段对齐、JNI 入口名称、无私有节点配置 / 日志 / 签名密钥。

具体计数、签名与校验值以交付包的 build-manifest.json 及本机忽略目录中的原始证据为准。

## 运行测试目前未通过入口

本机 adb 未连接手机，Android Emulator 的硬件加速驱动未安装。

软件模拟尝试：

- 官方 Android 17 x86_64 16 KiB 镜像：正常软件渲染、关闭 Vulkan、关闭 GPU、单核 CPU 软件模式均在启动前崩溃，退出状态 0xC0000005。
- 崩溃转储定位到 qemu-system-x86_64-headless.exe 内部的空地址读取。转储模块中没有 RegionHook.dll。
- 官方 ARM64 镜像：模拟器明确拒绝在 x86_64 主机使用该架构，未进入 Android。
- 没有安装驱动、改动 Windows 启动项或虚拟化开关，也没有改动正在使用的 Windows 启动器、代理服务和网络设置。

这些证据不能证明 APK 的 VPN、工作资料或真实联网功能已经运行成功。

## 必须补齐的运行验收

1. 在 Android 17 安装与启动，检查界面缩放、系统 VPN / 通知授权和工作资料创建。
2. 两个测试应用：一个加入环境，一个保持外部；比较启动前、连接中、停止后的 IPv4 / DNS / TCP / UDP / IPv6。
3. 证明工作资料的个人应用副本与同资料中的受控副本相互独立；已有个人 VPN 不被替换。
4. 用受控测试节点制造握手可用但 HTTPS 不通、TCP 重置、DNS 故障和 WebSocket 长连接，验证按需修复与不启动目标应用的失败路径。
5. 测试代理重启时保留 TUN，复用文件描述符后能重新转发；验证没有直连回退。
6. 系统终止 VPN 进程、手机重启、网络切换和撤销 VPN 权限时，验证工作资料的断网保护与恢复；确认个人资料仍能联网。
7. 记录实际使用的节点协议及 UDP 能力。HTTP 或不支持 UDP 的 SOCKS 节点不能按“UDP 正常”验收。
8. 未 Root 的任意应用地区 / 时区注入尚未实现；系统每应用语言设置不能代替该能力。

在这些项目通过前，安装包只能称为开发验证包，不能称为稳定安卓版或 Windows 版的完整等价替代。
