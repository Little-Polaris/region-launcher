# 局域网访问

从 alpha.26 开始，运行环境中的应用可通过 IPv4 访问局域网 SSH、NAS 和其他 TCP/UDP 服务。

| 目标 | 路径 |
| --- | --- |
| 127.0.0.0/8，非 DNS | 保持原 localhost 直连 |
| 10.0.0.0/8 | 局域网直连 |
| 172.16.0.0/12 | 局域网直连；不包含整个 172 网段 |
| 192.168.0.0/16 | 局域网直连 |
| 169.254.0.0/16 | IPv4 链路本地直连 |
| TCP/UDP 53 | 专用 DNS 优先，包括目标是路由器私网 IP 的请求 |
| 其他公网 IPv4 | 指定代理；失败不改走直连 |
| IPv6 | 仍禁用；IPv4 映射地址按实际 IPv4 目标处理 |

CGNAT（100.64.0.0/10）、Fake-IP（198.18.0.0/15）、组播及广播发现不作为本次局域网例外。使用局域网主机名时，仍需该名称能被专用 DNS 解析；SSH 使用局域网 IPv4 地址不依赖这项条件。

应用继续连接到本地转发器，由转发器按目标地址选择局域网或指定代理。这样无需修改全局路由、系统代理或后台服务，也保留绑定网卡、异步连接和 UDP 对端地址恢复。两种位数和子进程使用同一路由规则。日志用 `DIRECT LAN`、`PROXY SOCKS5`、`PROXY DNS` 区分路径。

规则在运行环境的转发进程启动时加载。升级后先保存工作，从托盘退出旧启动器，再覆盖新版、重启需要运行的软件；已有环境不会热切换规则。

## 检查

`tests/LanRoute.cpp` 检查网段边界；`tests/test_lan_broker.py` 检查 x86/x64 的 TCP、UDP、子进程、异步连接、网卡绑定、IPv4 映射、DNS 优先级及外部程序对照。公网代理与失败处理继续通过 TCP/UDP 和真实 HTTPS 回归验证。

2026-11-12 验证：代理端口不可用时，两种位数的局域网 TCP/UDP 均可用，外部对照连接正常；私网目标 53 端口仍交给专用 DNS，未配置解析器时也不会直连。公网代理失败保持失败，IPv6 阻断测试通过；真实 HTTPS 的国内与 Cloudflare 检测目标使用同一代理出口。

局域网 SSH 实测收到目标的 OpenSSH 版本响应，日志为 `DIRECT LAN`。系统自带 `ssh-keyscan` 随后报密钥交换算法兼容错误，未完成主机密钥获取，也没有进行账号登录。此次使用独立测试运行组，没有中断或重启用户当前的服务会话；完整运行环境升级后的 SSH 登录仍需在新会话中复核。
