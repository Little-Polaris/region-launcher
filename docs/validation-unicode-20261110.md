# Unicode DLL 路径验证（2026-11-10）

版本：0.3.0-alpha.5。启动器及公共接口模块改用 UTF-16 路径加载 DLL；已安装的网络服务、网络驱动和代理内核不变。

## 实现

原来的 `DetourCreateProcessWithDllExW` 仍使用窄字符串 DLL 名称。本版先用 `CreateProcessW` 暂停创建目标并加入 Job，再由小型 x64 加载线程调用 `LdrLoadDll`，传入完整 UTF-16 路径。加载成功后恢复目标主线程。`CreateProcessW/A` 子进程入口共用这一实现；调用方指定的 `CREATE_SUSPENDED` 保持有效。

DLL 从启动器所在目录加载。文件缺失、无效或加载超时会报错并终止目标，不恢复主线程。执行代码与路径数据分开分配，写入后执行页改为只读可执行；线程仍可能运行时不释放其内存。

## 本机结果

命令：`python -X utf8 tests/test_unicode_paths.py --network`。测试程序临时放在含中文、日文、空格和 emoji 的目录，结束后删除测试程序副本，保留日志。

- 旧版本在相同 Unicode 目录拒绝启动，已留存对照记录。
- 父子进程报告的实际 DLL 路径均为 Unicode 原目录；Unicode 程序名、文件读写、ANSI 子进程调用以及暂停子进程均通过。
- 缺失 DLL 和无效 DLL 均阻止程序进入主入口。
- 美国自动冬夏时间、固定标准时间、德国、日本、印度的地区语言传递和组外设置保持通过。
- WinHTTP/WinINet 默认代理与环境变量测试通过；组外默认值前后一致。
- 同一程序在组内 TCP/UDP 走测试代理，组外同时直接通信；子进程继承接管；代理拒绝时无直连回退。
- 10 条 Windows DNS 查询路径及异步查询通过；原始 IPv4 DNS 重定向、拒绝后不回退宿主缓存、组内 IPv6 TCP/UDP 阻断和组外 IPv6 正常通过。
- 停止事件、目标自然退出、会话进程退出三轮测试：外部 TCP/UDP 长连接与新连接共 1800 次通信，0 次失败。
- 宿主机 DNS、路由、系统代理、IPv6 网卡绑定快照前后完全一致。SHA256：`5B3371920A555E083FF42EE5B87343C3D0B038BE546D5D3E1253BBE2013F633C`。

证据位于本仓库忽略目录 `build/test-results/unicode-paths/`，生命周期明细在 `build/test-results/lifecycle-20261110-151601/`。

## 验证边界

远程加载线程会触发 Windows 加载器初始化。依赖 DLL 的初始化函数和 TLS 回调可能在公共接口模块之前执行；目标主线程暂停不等于所有初始化代码均未执行。目标已加入网络进程组，但此早期阶段的 DNS、代理和地区接口行为尚未验收，因此本版不承诺从最早初始化指令开始全面接管。

此次是 Windows 11 x64 的原生程序与 Python 集成测试，没有重新验收 Chrome 或 Claude Desktop 的完整操作；也没有进行外网出口、长时间负载、任意长度路径、UNC 路径或受保护进程测试。应用自身不支持 Unicode 路径的问题不在此次修复范围内。
