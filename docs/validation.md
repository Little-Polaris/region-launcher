## 宿主代理继承修复（2026-11-08）

用户提供的实际浏览器截图显示：国内出口仍为 `117.136.38.112`，海外出口为 `15.253.23.247`；DNS、WebRTC、洛杉矶时区和英语显示正常。读取当前宿主设置发现 `ProxyEnable=1`、`ProxyServer=127.0.0.1:7890`，测试浏览器网络进程 PID 33684 存在到该端口的连接。此前 curl 测试没有覆盖应用继承系统代理后由组外进程执行分流的路径，因此不能据其通过推断浏览器全部流量已接管。

新增公共 Windows 代理接口处理，作用于所有进入网络环境的目标进程及其子进程：WinHTTP 的系统默认代理查询、默认/自动会话及 WinINet 的默认会话返回/使用直接连接，交给已有包处理引擎；仅清除目标环境中的代理变量。普通地区测试模式不启用这些改动。没有修改宿主代理注册表、浏览器网络参数、服务协议或驱动。

`test_system_proxy.py` 在旧版上复现失败（仍返回 7890 及继承变量），修复版父子进程通过，外部查询前后相同。完整套件新增该测试；外网测试新增实际 WinHTTP 和 WinINet 请求。五项套件全部通过：curl、WinHTTP、WinINet 访问国内检测站均为 `15.253.23.247`，与 Cloudflare US 出口一致；本轮 DNS 见证为 US / Cloudflare `104.23.250.85`；组外出口及宿主配置前后不变。地区、冬夏令时与文件访问回归通过。

修复版输出为 `build/system-proxy-bin`。新增系统 DLL 依赖属于 Windows 自带 WinHTTP/WinINet；本轮不需重新安装服务。仍需在修复版实际浏览器中确认国内出口及完整颜色，不能将修复前截图当成修复后验收。应用显式代理或自行读取注册表的路径不在本次默认代理修复的覆盖范围内。

## 0.3.0-alpha.1 统一网络原型（2026-11-05）

本轮按进程组和公共 Windows 接口重做网络与 DNS 路径。界面对所有程序执行相同流程，程序参数来自用户输入。新原型尚未替换原来的桌面入口。

### 已完成的真实网络验证（加入 IPv6 禁用要求之前）

- 同一原生程序内外并行：组内 TCP/UDP 经过代理，组外直连；子进程归入组内；SOCKS5 拒绝连接时组内没有退回直连。
- 普通 curl 通过统一进程环境访问 Cloudflare 与 my.ip.cn，均为 `203.10.97.121`，Cloudflare 国家为 US。未传入代理或 DNS 专用参数。
- 同时运行在环境外的普通 curl，测试前、测试中、测试后均为 `117.136.38.90`。
- Python 与原生程序使用不同随机 DNS 见证。最终见证仅返回 `162.158.89.76`、`162.158.89.228`，检测服务均标识为 US / Cloudflare。原生测试还直接发送了 DNS 数据包。
- 初期只设置进程默认 DNS 的方式未通过；后续一次真实测试也发现国内解析器。最终使用明确的查询服务器、公共查询选项、独立缓存路径，并保留 IPv4/IPv6 联合解析语义后，上述真实测试通过。该结果属于当次网络条件，不是对任意应用或任意版本 Windows 的保证。

## 0.2.0 独立全代理（2026-11-05）

本机原来的 Clash Mi 7890 为 rule 模式，包含国内直连规则及国内 DNS。浏览器经该入口仍可能得到国内站点直连出口。因此新增独立 Mihomo 1.19.33 内核、仅回环监听的 17890 入口、固定美国节点与唯一 MATCH 规则。网站 DNS 经节点访问 Cloudflare DoH；导入时经已有代理完成节点自身的加密解析，并固定服务器 IP，避免启动时依赖系统 DNS。节点入口变更后需重新导入。

实测（`tests/test_live_exit.py`，使用 SOCKS5 远端域名解析）：

- 新通道 Cloudflare trace：203.10.97.121，US。
- 新通道 `https://my.ip.cn/`：203.10.97.121，与海外出口相同。
- 同时保留的 7890 访问 `https://my.ip.cn/`：117.136.38.90，原有分流未被切成全局模式。
- `2026.ip138.com` 在测试时返回 HTTP 404；按检测页的备用来源使用 my.ip.cn，未把失败视为通过。
- 使用检测页实际的随机子域名及 `/api/dns/result/` 接口，观测到 104.22.50.101、104.22.194.84、162.158.185.27、172.64.216.83，页面地理接口均返回 US / Cloudflare；没有出现 CN 解析器。此结果是一次实测，不是对所有网络条件的保证。
- 两项配置回归测试及实际程序集 STA 入口检查通过；发布构建成功。
- 桌面实际点击“检测代理”，独立内核自动启动且 SOCKS5 握手通过；选择 chrome.exe 后点击“启动所选程序”，界面进入独立浏览器启动流程，使用 17890。

此次没有修改 Clash 配置、系统 DNS、路由或全局代理。发布压缩包从干净目录组装，不包含浏览器资料或节点凭据。上述在线证据来自请求测试，尚未取得新版浏览器内完整检测页截图。普通应用的系统服务代发 DNS 等边界仍保留；Claude Desktop 仍未验证。
