# 实际联网检测和日志

点击“检测联网”，或启动软件前，启动器按以下顺序检查：

1. 验证独立代理仍为固定 `MATCH,RegionExit` 路由和专用 DNS，拒绝直连规则或全局 TUN 配置。
2. 启动自己的 Mihomo 内核并完成本地 SOCKS5 握手。
3. 明确通过启动器的 SOCKS5 端口访问 Cloudflare 和国内 IP 检测站，验证 HTTPS 返回状态、响应中的 IPv4 地址，并记录耗时。
4. 经 `RegionSession` 在运行环境内启动独立检测进程。此进程不指定应用级代理，使用和所选软件相同的通用网络接管路径，再访问这两个站点。
5. 比较同一站点两层检测的出口。没有实际成功请求、没有可比较站点，或两层出口不一致时，阻止本次软件启动。

两层均至少一个站点成功且有相同站点出口可比较时通过；单站失败仍单独显示，不表示所有网站均可用。单次请求上限 15 秒，环境检测进程上限 60 秒。运行期间也可点击检测，检测程序加入当前环境，不结束已有程序。

检测使用启动器保存的独立节点，不使用 Clash Mi 或系统默认代理作为回退。系统代理和浏览器代理、DNS 设置不修改。保存新节点后先停止旧内核，下次检测或启动重新加载；运行中手动修改配置会提示重启启动器。

检测结果只证明该检测进程在当时的 TCP/HTTPS 路径。它不能代替具体应用、单实例复用、UDP、全部 DNS 路径或长期稳定性验收。国内网站速度快不等于直连；查看实际出口、内核 `using RegionExit` 和后台 PID/目标连接记录。轮换出口节点可能导致两层出口不同，此时会阻止启动并提示原因。

## 日志位置

“打开日志”进入 `app/data/logs`。启动器自动记录带毫秒和时区的时间、版本、内核与目标 PID、检测阶段、站点状态/耗时/出口、启动退出和异常。Mihomo 的运行副本使用 `info` 日志级别，保留连接使用的路由记录；原节点配置文件不改动。

- 每个日志文件约 5 MiB 后轮转，保留最新十份（约 50 MiB；单条超长输出可能超过单文件阈值）。
- 检测详细结果在 `app/data/sessions/check-编号/connectivity.json`；日志中记录检测编号。
- 检测结束、停止请求和正常会话结束时，尽可能保存后台 `network.log` 的末尾快照；无法读取时也会写出原因。后台原日志仍在 `C:\Program Files\RegionLauncherNetwork\logs\network.log`。
- 不主动记录完整启动参数、私有节点 JSON、订阅链接或网页正文。已知节点凭据和常见密码、令牌、认证头、URL 查询参数会遮盖。第三方程序输出仍可能带个人路径、域名或未识别的敏感内容，分享前请检查。
- 文件写入失败会在界面提示。日志、检测会话、私人配置均不进入 ZIP。

## 验证

自动测试覆盖握手成功但 CONNECT 失败、错误响应内容、超时、禁止直连回退、出口不匹配、直连路由拒绝、UTF-8 文件日志、常见凭据遮盖和轮转保留。

已验证运行中加入检测进程后，原环境及其已有程序继续运行；检测日志保存了内核路由和后台网络快照。GUI、软件列表和七种协议配置回归通过。

2026-11-10 本机独立节点实测：指定代理与环境内检测的两个站点均返回 HTTP 200，IPv4 出口均为 `15.253.23.247`，Cloudflare 返回地区 US；宿主 DNS、路由、系统代理和 IPv6 绑定快照一致。原始证据保存在仓库 `build/test-results/connectivity/live` 和 `build/connectivity-live.log`（不进入安装包）。这不是用户之前无日志访问的追溯结论。

实现参考：[.NET SOCKS 代理支持](https://devblogs.microsoft.com/dotnet/dotnet-6-networking-improvements/)、[Cloudflare 检测端点说明](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/)。
