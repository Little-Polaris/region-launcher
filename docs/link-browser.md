# 授权链接浏览器

点击主窗口“授权浏览器…”选择自动、Chrome、Edge，或者软件列表中某个已保存的独立浏览器配置。保存后，重新开始一次运行环境。

自动选择优先使用软件列表里程序存在且带绝对路径 `--user-data-dir` 的 Chrome / Edge 条目；多个条目时按列表顺序选择，也可以在对话框明确指定。系统原始 Chrome / Edge 默认资料目录及其子目录不作为独立资料。不会复制原资料，也不会继承条目中的代理参数；只读取程序路径、独立资料目录和可选的 `--profile-directory`。

打开 HTTP / HTTPS 链接时：

| 资料状态 | 行为 |
|---|---|
| 保存的独立资料未使用 | 在当前环境启动浏览器 |
| 资料已被当前这次环境的浏览器使用 | 复用该实例，保留登录状态 |
| 资料被外部浏览器或另一运行环境使用 | 改用本次环境专用的临时资料 |
| 没有保存的独立资料 | 使用临时资料 |

临时实例使用 Chrome 无痕窗口或 Edge InPrivate，通常需要重新登录。临时资料放在 `app/data/link-browser-temp/<本次环境编号>/`，整个环境结束后清理；浏览器文件短暂被占用时可能延迟清理，日志会记录。已保存的资料保留。每个环境使用不同的临时目录；不要手动用外部浏览器打开正在使用中的启动器专用资料。

浏览器仍由统一的子进程注入与网络服务接管；没有添加代理、DNS 或 WebRTC 浏览器参数，也没有更改系统默认浏览器。新实例继承打开链接程序的地区设置；复用的实例保持它启动时的地区设置。临时无痕模式本身不负责网络隔离。

覆盖 Windows `ShellExecuteW/A` 和 `ShellExecuteExW/A` 打开的 HTTP(S) 链接。从 0.3.0-alpha.32 起，也识别 Electron 等程序传入的外层带引号的网址。找不到指定浏览器或启动失败时记录错误，不自动交给外部浏览器。其他协议、程序自行连接外部已有进程、绕过这些接口的 COM 激活不在覆盖范围内。

配置位于 `app/data/link-browser.json`，例如 `{"Choice":"auto"}`；选择值还包括 `chrome`、`edge` 和 `app:<applications.json 中的条目 id>`。授权网址和其中的令牌不写入新增日志。

Edge 的路径查找、InPrivate 参数和接口处理有自动测试。本机未安装 Edge，实际 Edge 授权页面仍需在有 Edge 的设备验证。ChatGPT 的完整账号授权必须由用户在更新并重启环境后操作。

## 本次验证

- 原生接口：Chrome / Edge 两种程序名 × 四种 ShellExecute 接口 × 五种场景，共 40 个组合，包含外层带引号的链接。另验证浏览器缺失时停止打开、中文路径和日志保护。
- 真实 Chrome：通过本机回环测试页验证普通链接和带引号链接在同一个受控浏览器进程打开。覆盖保存资料、临时资料、外部资料占用和会话结束后的临时目录清理。
- 子进程自定义环境继承、统一 TCP 代理及 IPv6 阻断回归通过；软件配置选择与界面回归通过，界面截图已检查。
- 这些测试不等于 ChatGPT 实际账号授权、远程设备连接或真实 Edge 的端到端验收。
