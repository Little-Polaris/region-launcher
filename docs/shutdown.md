# 退出与端口检查

alpha.27 从托盘退出时，依次取消未完成的检测/启动任务、结束自己的运行组、停止自己持有的代理内核，然后检查监听地址是否可重新绑定。点击窗口叉号仍只隐藏到托盘。

代理所有权来自启动时持有的进程对象和句柄。只结束这个代理，不按进程名称、端口占用 PID 或子孙进程扫描结果批量结束进程。终止后最多等待 10 秒并检查结果；未确认退出时保留句柄、记录失败，不启动替代内核。代理退出后最多等待 3 秒检查端口；正常释放立即继续。

启动前及退出后均检查代理地址 `127.0.0.1:配置端口`（默认 17890）以及专用 DNS `127.0.0.153:53` 的 TCP、UDP。检查采用短暂的独占绑定，完成后关闭检查套接字；不改变端口配置，也不强制复用占用中的地址。

日志包括：

- `[代理退出]`：自有 PID、创建时间、终止等待结果、退出码和耗时。
- `[端口检查]`：启动时冲突的协议、地址、端口和 Windows 错误码。
- `[端口释放]`：实际重新绑定检查结果，明确区分成功和超时。
- `[端口快照]`：匹配的 IPv4 TCP 状态、UDP 绑定及 PID；分别记录进程已不存在、信息不可读或系统没有提供 PID。快照最多显示每种协议 12 条。IPv4 表没有匹配项不等于绑定成功。

代理内核加入随启动器结束的 Windows 进程组：启动器未走正常退出（任务管理器结束、崩溃、注销或关机、安装程序强制结束）时，Windows 会一并结束代理，不再留下继续占用 17890 和专用 DNS 的内核。启动代理前还会检查本安装目录的 `proxy\mihomo.exe` 是否仍有实例在运行而其启动器已不存在（含旧版本遗留），确认后结束它再检查端口；只匹配本安装目录的内核文件和当前会话，不涉及其他位置的同名程序，也不涉及启动器仍在运行的实例。日志前缀为 `[代理生命周期]`、`[代理回收]`。

如果进程已退出但地址仍不可绑定，会保留失败记录，不通过关闭外部程序、重置网络或停用驱动处理。端口快照仅供诊断；它与进程查询并非原子快照，不能用于认定进程所有权。此次改动不保证解决所有系统驱动或内核资源延迟释放的问题。

验证使用独立端口和测试进程：真实 Mihomo 连续三次启动/退出/重新绑定、保留活动连接时退出、代理与 DNS 的四种 TCP/UDP 冲突、外部监听存活、重复清理，以及托盘退出的进程组/代理/端口检查。当前用户正在运行的实例不参与退出测试。
